# ConfIt v0.9 design

Design spec behind v0.9.

Status: In progress

## Motivation

Even at 300 MB the tool eats like an electron app
while doing a cli job. I installed mete and worked through
the findings beside the agent, and the architecture
failed in three places at once.

I said that effects happen in cli alone, but they
scattered across every module through the old
filesystem trait. The trait kept test code clean
and left ownership unclear instead. Surface code, supposed
to only translate Lua into Rust, held a 500 line file
uncompressing data.

Core did everything, literally everything. Cli called
core for everything. Core held the effects, the data
transforms, the logic, the shared entities. Everything
else lived inside it, beside Lua evaluation and parts
of compression.

v0.8 lowered memory use and left its base in place. I
removed whole-bundle materialization, but the code
materialized everything everywhere. Lua held it in
gc, Rust held it many times for comparisons
and through the whole run, downloads, archives and
their contents, whole trees. The trait I built returned
Vectors, closing every streaming path even where I
wanted it open.

The app grew more complex with the domain less clear
at every step. The resource idea stayed in my head, and
telling a resource (profile input) apart from a
route (profile output) stayed hard. The old trait tested
well and reused badly, I passed it through every layer and
rewrote large portions to change small things.
I had to stop 0.8.1 for 0.9. Making it lazy
meant rewriting nearly 80% of the code, and the
integration tests broke in the same move for depending
on everything.

## Objective

Make the domain clear. Split apply-time resources from
plan-time resources. Share one filesystem shape, so one
implementation serves runs and tests. Lazy filesystem
access.
Split responsibilities across crates and
modules. Each piece of work happens once. Trusted sources,
types holding valid states alone.

## Goals

- Seal identity once, so every layer trusts the
  sealed type and validation runs once at the edge.
- Split plan-time resources from apply-time documents,
  so inputs and outputs stop sharing one shape.
- Preview without touching the disk, so a preview
  changes nothing.
- Bind destinations late, so bundles travel across
  users and platforms.
- Shrink the surface to handles, so every value
  between layers passes through handles.
- Stream large bytes, so archives and blobs
  travel in chunks.
- Fail old artifacts with a clear error, so each
  version owns its shapes.

## Plan

### Identity sealed at the source

The v0.4 split divided by dependency class before I
knew the domain, and I regretted centralizing
everything as pure data behind one trait for all
files. This split divides by domain now that I know it.
Trusted sources arrive with their hash and every
layer downstream trusts the type instead of
re-proving the bytes. The types hold valid states
alone.

### Plan-time and apply-time split

Profiles take resources and return documents, two
sides meeting at evaluation. Resources feed the
plan as urls, project files, and archive members,
everything Lua reads to decide. Documents outlive
evaluation. Payloads land at routes on the applying
host. The old shape merged both into paths, so inputs
and outputs shared one shape and every layer re-proved
them. Each side owns its names, and everything
crosses evaluation sealed.

### Crates follow the domain

The filesystem is one struct with different behavior
in tests and in prod. The model
holds the portable language, built on data alone.
The store keeps pools, caches, slots, and bundles.
The runtime touches destinations alone. The engine
translates Lua over handles. The cli wires runs. Each
side declares its own actions where they run, and
each caller uses its own verbs.

### Surface shape

My idea keeps the confit core as simple as
possible: the engine does only what Lua
cannot do, and plugins add the flexibility.
With that I move from globals to require,
mainly to simplify plugins. Today a plugin
.lua file looks like a require module but
still needs a .d.lua pair telling the
language server it lives in the global.
That pairing breaks easily and is hard to
explain, so plain require stays simple.

New core modules load through require under
`confit.<module name>` names, one module per
concern. The chunk sandbox exposes require
with checked globals alone, and the bare
confit global stays nil. A plugin declares
---@module and that is all, one file holds
code with types.

```lua
local fetch = require("confit.fetch")
```

Destinations are plain tables holding a
base with segments, so profiles build them
as literals. A bundle travels across
machines and users while a baked string
names one machine and breaks on the next,
so values resolve on the applying host for
the applying user. Literal covers host
specific absolute paths and stays on one
machine. Text slots stay
strings.

```lua
local bashrc = { base = "home", relative = ".bashrc" }
```

`confit.resource` seals a file under the
project folder and `confit.fetch` seals a
url, both returning the same resource
handle. Two verbs because the inputs
differ: digest pins fit urls alone,
network use shows on the import line, and
no call reads a string for a scheme. One
value holds every view, text with sha.
Absent reads produce nil with reason, so
profiles branch without pcall: a failed url
reads absent like a missing file.

```lua
local resource = require("confit.resource")
local handle = assert(resource("starship.toml"))
local text = assert(handle:text())
```

```lua
local fetch = require("confit.fetch")
local remote = fetch("https://example.com/tool.tar.gz")
```

`confit.tree` builds a managed file set from
a destination with a nested map. A handle
is a file and a table is a subfolder, and
plain Lua filters members before building.
A for loop restates the whole picker
protocol, so core keeps no filtering
code. Filtering that keeps nothing
builds an empty folder. The caller
rejects it.

```lua
local files = {}
for _, name in ipairs(archive:members()) do
  if name:match("%.ttf$") then
    files[name:match("[^/]+$")] = assert(archive:member(name))
  end
end
mine.documents[dest] = tree(dest, files)
```

`confit.template` renders text for any text
slot, vars hold plain values alone.
`confit.version` returns one integer, so
profiles report breaks with custom
messages.

On the data side, several things living as
userdata today turn into plain data.

The first one is Config, it has no use for
userdata, it is pure data, one name string
with document and hook vectors. Profiles build it with
literals, pass it through helpers, filter
it with conditionals, and return it. A
sugar plugin offers the add helper, so authors
keep method syntax and core keeps no
construction code. Using one path twice is
a hard error, and map order never matters
because assembly sorts by path.

```lua
local mine = { name = "bat", documents = {} }
config:add_document(mine, dest, { text = "content" })
mine.documents[other] = { format = "toml", data = { profile = {} } }
```

Documents work the same way, destination
values with body tables. Bodies show their
kind through separate markers, text
with format and data with target with
blob, because editors list every kind's
fields together and cannot narrow a table
by its first key. Hooks are plain tables
too, argv with guards, and patches are
plain tables holding their callback
functions. The same checks use `validate_*`
verbs returning bool with reason, so authors
check shapes early.

```lua
local ok, reason = validate_document({ text = "content" })
```

Require returns stock modules under project
containment. Dotted names resolve to
project files with folder entries falling
back to their plugin folders, and links
resolve inside the project. Plugin callers
stay inside the plugin tree while project
code requires anything contained, so an
escape fails the plan with the bad name.

### Explicit shells with filter patches

Shell templating with `{{shell}}` no longer
fits the app. The first idea made shell
one fact among others with a fact api
over templating. But shell never fit
there because shell is not a value.
Shells are documents, one rc document per
shell. A fact returns one value for one
slot, while a shell picks a whole
document. Filter patches replace
templating. One patch runs across all rc
documents, and each call receives the
target route so the callback knows which
shell it patches.

Profiles no longer list shells. The
profile lists every shell document and no
hidden document appears. Patching a
missing document no longer creates it, so
a mistyped target fails the plan instead
of creating a new document.

Patches take a target or a filter, never
both. A filter names a kind with a match
over destination display, defaulting to
all. One patch runs across every matched
document in destination order, so
first-wins stays fixed. Each call receives
the target route beside the data handle,
so the callback knows which shell
it patches:

```lua
{
  filter = { kind = "rc", match = ".*" },
  apply = function(route, data)
    local shell = route.relative:match("^%.(%a+)rc$")
    data:add("profile", { eval = { "mise", "activate", shell } })
  end,
}
```

Mise uses one filter patch over all rc
documents with no shell code anywhere.
Facts are plain eval values like version
and os, returned on the spot with no
waiting variant, since the engine resolves
everything at eval and bundles hold
one host.

### Streaming shape

Archives unpack entry by entry, blobs stream
from files through gzip, drift checks opaque
payloads by hash alone. Text and structured
payloads stay inline in the manifest as
data, rendered and compared in memory.
