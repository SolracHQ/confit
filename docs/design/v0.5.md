# ConfIt v0.5 design

Design spec behind v0.5.

Status: Implemented (sealed 2026-09-16)

## Motivation

v0.4 previews. I want the full flow working somewhere real: start
a project, create real config files, download and unpack real
content, open a shell where the setup works, hand-edit a file and
watch the next plan show the drift. A container run proves the
loop. Everything in this version serves that flow.

## Objective

Support a more complete workflow from initializing the project to
creating real files.

## Goals

- Split stubs per namespace plus per plugin, so users follow one
  file per surface. The global keeps shared shapes, every surface
  reads alone.
- Scaffold projects with `init`: plugin stubs, namespace stubs,
  one profile with one rc document. Starting a project means one
  command plus the manual.
- Apply files to disk with preview-then-prompt, drift re-prompt,
  previous-states rotation plus recover. Creating files earns
  trust through prompts and a way back.
- Fetch text plus files with optional sha guarantee. Cache
  downloads beside sha sidecars with re-download on mismatch
  plus a `--re-fetch` flag. Remote content behaves like local
  content with a URL attached.
- Unpack archives through `confit.document.compressed` with a
  user callback returning documents. Filters express extension
  picks, executable picks, and content picks alike.
- Add the opaque kind for binaries. Base64 payloads in the plan,
  raw bytes on apply, hash plus size drift.
- Prove it in the container: configs land, downloads unpack,
  setup works, hand-edit plus re-plan shows drift.

## Plan

Each part below takes one goal from above and records the
decisions behind it.

### Stubs split

One file per surface. The global keeps shared shapes. Each
namespace moves to its own file. Each embedded plugin keeps its
own stubs. The split deletes the stale entry classes left over
from the `RcOp` unification.

### `init`

`confit init [DIR]` scaffolds a project with plugin stubs, namespace
stubs, and one profile holding one rc document plus commented
pointers into the manual. I made the target a positional defaulting
to `.` because starting a project means one command in the folder
I already stand in. Stubs copy as files. What the user reads is
what the binary ships.

### Apply, files only

Apply is conceptually simple. It creates every document in its
place. The behaviors around it carry the weight.

The run previews first, then prompts:

```sh
$ confit apply
Plan: 2 to add, 0 to change, 0 to destroy.
Apply these changes? Type 'yes' to continue: yes
```

Only the literal `yes` proceeds. Anything else aborts with
nothing written. A plan file flag skips the preview, because a
reviewed plan needs no second reading. A force flag skips the
prompt. Drift re-prompts always, because the world moved since
the preview.

Previous states live in user global state, under the OS config
folder. One fixed slot holds the live state. I keep a single
global slot because the machine owns the applied result, and a
`--state` flag overrides it per run for experiments beside the
real thing. A plan holds version plus documents plus `created_at`
alone, so history answers when each plan applied. Rotation keeps
five. `recover` lists `index @ created_at` and re-applies the
picked one.

### Opaque documents

Binaries need a home. Structured text cannot hold them. A new
opaque kind carries base64 payloads in the plan and renders raw
bytes on apply. Drift compares hashes plus sizes, never content.
Same shape as every other document, same path key, same prompt
posture.

### Fetch primitives

Text and files answer different questions, so they are separate
primitives. A pinned sha is a guarantee, not a lookup key. Half
the time I cannot know the sha upfront. Kubectl latest takes
four fetches: the version pointer, the binary, the sha file,
and the comparison in my head. The plan records what the
network gave back, because different web resources produce
different results and the diff says so:

```lua
local stable = confit.resources.fetch_text("https://dl.k8s.io/release/stable.txt")
local base = "https://dl.k8s.io/release/" .. stable .. "/bin/linux/amd64/kubectl"
local bin = confit.resources.fetch_file(base)
```

`fetch_text` returns the body as a string, for version pointers
and templates and anything Lua wants to read. `fetch_file`
downloads into the OS cache folder through the dirs crate and
returns the local path. Beside every cached file sits a sha
sidecar. A fetch re-downloads while a file or its sidecar
misses, while the bytes mismatch the sidecar, or while the
`--re-fetch` flag passes. Otherwise the cached file serves the
plan with zero network. Downloading 450 MB on every plan
because some small thing changed is crazy, and the sidecar is
what prevents it. A user-supplied sha stays an independent
guarantee checked against local bytes or remote bytes alike,
and mismatch fails the plan.

### Compressed documents

First version to work over. The engine unpacks gzip, tar,
plus zip archives. The callback runs per member and returns a document,
because the path is the key of documents and only a document
carries one. Returning nil skips the member:

```lua
confit.document.compressed("fonts.tar.gz", function(path, info, content)
  if path:find("%.ttf$") then
    return confit.document.opaque(font_path(path), content)
  end
end)
```

Path, meta, and data all feed the decision, so filters express
extension picks, executable picks, and content picks alike.

## Out of scope

Hooks, command execution, installer running, apply-behavior
config file, source-document kind.
