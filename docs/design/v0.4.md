# ConfIt v0.4 design

Design spec behind v0.4.

Status: Implemented

## Motivation

v0.3 exists on paper and half built. Fifteen thousand lines of
patches over patches, legacy names, broken tests. I pressed TDD so
hard I tested hashes instead of business logic while the business
logic kept moving. The result was impossible to maintain.

The scope swung hard across versions. v0.1 built a complex Rust
framework with simple Lua. v0.4 builds a simple boring API and moves
extensibility into plugins. The culprit chain became plain patch
callbacks. Merge rules became priority plus declaration order.

The layered architecture came from my web hobby background and a zig
library, and it felt convoluted in Rust. One Lua callback crossed
three data transformations. The biggest error was centralizing all
data as pure data in `model`. The dependency graph looked clean and
development became hell. No impl blocks, everything as free functions
moving data through 5 to 10 params. I optimized the graph and lost
the code.

## Objective

Boring Rust, clever Lua. Three crates split by dependency class:
pure logic, Lua execution, effects. The engine boundary returns
finished documents. Behavior lives beside its data. Tests assert
business logic alone.

## Decisions

Three crates with three allowed edges. `confit-core` holds types
plus their pure functions. `confit-engine` holds every Lua touch.
`confit-cli` holds args, files, terminal, logging. `cli` reads
`engine` and `core`. `engine` reads `core`. Nothing else.

`engine::evaluate` returns `Vec<Document>`. Configs, patches,
shells, and owners never cross the boundary. Shells expand to
per-shell rc documents inside the engine.

One path holds one document. Repeats fail as plan errors naming
the path. Documents carry no owner. Patch owners stay inside the
engine for sort order plus collision lines.

Rc sections are position plus guard. Any entry renders in any
section. The guard splits profile from the rest. Entries render
in declaration order. Patches run in pipeline order, priority
desc plus owner asc, op order verbatim.

The `Filesystem` trait plus the memory fake return before any
writer that matters. Tests never touch home folders.

Plan format reads version 2. Version 1 covered artifacts and
reads incompatible.

## Out of scope

`apply`, `explain`.
