# ConfIt v0.3 design

Design spec behind v0.3.

Status: Draft

## Motivation

v0.1 follows pulumi plus terraform and grows past its scope. Special
cases everywhere. Three fold functions plus overwrite relations for
something that never happens, plus special flags hunting culprits.
Feature creep in my first version. The Lua API fills with special cases
too. Every tool takes an installer, so asdf or Windows-scope users wait
on me for support.

Rust is heavy for this. Lifetimes, iterators, borrow tracking, all to
know who touches an env var to leave a comment. That was dumb.

I want it simple, I want it boring. The engine defines the data shape,
builds configs as bundles of documents, stores a plan, applies that
plan into files. RC becomes one more document. Mise leaves first-party.
Ergonomics live in plugins. Explicit means verbose, plugins cover that
as the middle layer. Lua holds references with no ownership rules and
callbacks run like silk.

RC is a weird monster. One file sets up the environment, dresses the
interactive shell, then runs programs last. My model treats it as one
bag and it fights back.

Profiles load only the configs they need. Loading every plugin inverts
that, so unused plugins stay unloaded until use. A bad script inside an
accidentally installed plugin never runs on its own.

## Objective

Grind v0.1 down to a boring base with a cool framework on top. The
engine grants documents plus patches plus small sharp tools that
build values. Installers become Lua plugin namespaces over those
primitives. Structured data merges through callbacks users write, run
in pipeline order. Shell entries gate behind runtime conditions, files
land unconditionally. RC renders three groups in fixed order.

## Goals

- Replace the Tool abstraction with Config, a simpler bag of documents.
  Documents, patches, configs are the only concepts. Profiles declare
  machine-owned bases, anyone declares, repeats fail, patches create.
- Merge structured data through user callbacks over a data proxy, run
  in pipeline order, with one log line per overwrite as witness.
- Ride priority as five-level data on patches. The engine sorts and
  never interprets beyond order.
- Move installers plus ergonomics into lazily loaded Lua plugin
  namespaces over boring primitives.
- Render RC as setup, interactive, final groups in fixed order. Shell
  entries gate behind runtime conditions, files land unconditionally.
- Keep whole documents unmerging. Warn conflicts, escalate to a plan
  error on demand.

## Plan

Each part below takes one objective from above and records the decisions
behind it.

### Documents Plus Configs

Three concepts, nothing else. Documents are the final deliverables.
Patches modify documents. Configs hold documents plus
patches. Profiles hold documents plus configs.

```lua
-- profiles/desktop.lua
local rc = require("documents.rc")
return {
  shells = { "bash" },
  documents = { rc },
  configs = { bat, starship },
}
```

Profiles declare machine-owned bases, configs declare tool-owned
documents or just contribute. Anyone declares, repeats fail hard.
A patch to an undeclared document creates it, so patches never
fail this way.

Documents exist so patches carry no base argument. Declaration
holds the starting content, patches hold tweaks only.

Tool primitives go away. The name never fits, fonts are not tools, and
each installer as a primitive means fresh Rust per installer.

### The RC Document

```lua
local rc = confit.document.rc
local path = confit.path
local shell = confit.shell
return rc.new({
  profile = {
    rc.path_entry(path.home(".local/bin")),
    rc.eval({ "mise", "activate", shell.SHELL }, { when = shell.in_path("mise") }),
  },
  config = {
    rc.alias("ll", "ls -l"),
    rc.alias("la", "ll -a"),
  },
  final = {
    rc.eval({ "starship", "init", shell.SHELL }),
  },
})
```

Every key stays optional, `rc.new({})` reads valid. Unknown keys fail
as plan errors, misspells never create phantom sections.

Setup first, environment plus profile plus path, always executed.
Mise installs shims into `.local/bin`, so the base leads with it on
PATH. One guard follows, non interactive shells return there. Interactive
second, aliases. Final last, the init list in listed order. Multiple
inits coexist as one ordered list
and execution follows listed order within each lane.

Init entries take a lane, `first` or `last`, default middle. Nim
initializers ride first, starship plus sdkman ride last.

```sh
export PATH="$HOME/.local/bin:${PATH}"
if command -v mise >/dev/null 2>&1; then
  eval "$(mise activate bash)"
fi

case $- in
*i*) ;;
*) return ;;
esac

alias ll='ls -l'
alias la='ll -a'

eval "$(starship init bash)"
```

`profile_path(dir)` stays prepend sugar for `PATH`. Init strings render
a `{{shell}}` slot with the target shell name, so one entry addresses
every shell.

### Patches

```lua
local rc = confit.document.rc
local shell = confit.shell
local c = confit.patch.rc(function(document)
  document:append("config", rc.alias("something", "else"))
  document:set("config", rc.alias("ll", "ls -la"))
end)
c:priority(confit.priority.MAJOR)
```

The callback receives the document proxy. `set` writes one path,
`append` extends one list. Paths hold dotted keys plus single indices,
one path per call (`a.b[0]`).

Pipeline order is priority desc, name asc. Op order inside one callback
is preserved verbatim. `set` over a path another patch wrote
records a collision line, silent wipes read as engine bugs otherwise.
`append` onto a non-list fails as a plan error.

Priority holds five levels, `MINOR`, `LOW`, `NORMAL`, `HIGH`, `MAJOR`,
default `NORMAL`. One level rides each patch. Two patches
from one config with different levels scatter across the document, that
stays expected. Deterministic scatter beats hidden order.

```sh
collision on alias "cat": "eza" overwritten, "bat" wins
```

Entries carry `when` through opts, so guards ride along into the
document:

```lua
document:append("config", rc.alias("cat", "bat", { when = shell.in_path("bat") }))
```

### Structured Documents

Structured data is data plus a serialization format. Documents declare
content, patches modify it through callbacks:

```lua
confit.document.structured("json", {
  user = { theme = "catppuccin", extensions = {} },
})
```

```lua
confit.patch.structured("json", function(data)
  data:append("user.extensions", "com.microsoft.extensions.python")
  data:set("user.theme", "catppuccin")
end)
```

Reading text plus decoding stays useful. Users load a shipped document
as declaration content, then modify it with patches:

```lua
local text = confit.resources.load_text("resources/starship.toml")
local base = confit.codecs.decode("toml", text)
confit.document.structured("toml", base)
```

The old `toml`, `json`, `yaml` constructors go away. The engine grants
atoms instead, plugins compose them. `resources.merge` leaves the
engine and returns as a Lua plugin over plain tables. File reads stay
in the engine, reads stay jailed.

### Plain Text Plus RC Plus Link

Four document kinds cover everything, structured plus plain text plus
rc plus link. Structured plus rc take patches, plain text plus link
read declaration only. Template disappears as a kind and returns as Lua
functionality over `load_text` plus a render atom plus a plain text
document.

Same path with different bytes warns naming path plus owners. Whole
documents arrive ready to use, merging them is probably an error or a
race. `--strict` escalates the warning to a plan error.

### Priorities Are Data

Priority rides each patch like any other field. The engine sorts
by it, never interprets beyond order. Five levels cover every case I
meet, integers allowed any value and therefore meant nothing.

### Plugin Namespaces

Installers live in plugin namespaces, defaults embedded in the same
shape as external ones:

```lua
local mise = confit.plugin.solrachq.mise

local bat = mise.package("bat", function(rc)
  rc:alias("cat", "bat --colors=always")
  rc:alias("c", "bat")
end)
return bat
```

One call builds the config under the package name, declares the
install, sets `when` on every entry from the callback against the
binary. Activation ships as a plain entry builder beside it:

```lua
mise.activate()
```

Mise activation becomes an ordinary `eval` init document entry the
plugin adds, visible plus editable like any other entry.

### Plugin Loading

A `--plugins [path]` global flag points at the plugin folder. Inside
it each plugin keeps its own folder:

```sh
{user}/{name}/plugin.lua
```

Embedded defaults load always, in the same shape as external ones.
Colliding names note-and-skip to stderr. Reads stay jailed to the
plugin folder, traversal fails as a plan error. Extra plugins load
lazily on first access.

### Pipeline Order

Every transform runs in pipeline order, priority desc plus name asc.
Registration order changes nothing. Each run records one collision line
per cross-patch overwrite and prints the log path after the
summary:

```sh
$ confit plan --profile profiles/desktop.lua
Plan: 2 to add, 0 to change, 0 to destroy.
log: /tmp/confit-123.log
```

`--log-file` sets the path explicitly.

Stored provenance goes away. The chain tracks who-overwrites-what
through every layer for collisions I never see, not once in my old
dotfiles. Pipeline order plus collision lines cover the hypothetical
for almost zero machinery.

### `when` Extension

Conditions build in Lua, evaluate in the shell. The plan emits
unconditionally, each fresh session skips entries that lack their
binary. Fresh machines need zero special rules, entries sit inert
until the install lands, then activate on the next shell.

Entry builders take `when` through opts:

```lua
rc.alias("cat", "bat", { when = shell.in_path("bat") })
rc.alias("c", "bat", {
  when = function(shell)
    return shell.all({ shell.in_path("bat"), shell.exists("~/.config/bat") })
  end,
})
```

Render emits plain entries with guards inline. Groups separate by
blank lines:

```sh
if command -v bat >/dev/null 2>&1; then
  alias c="bat"
fi
```
