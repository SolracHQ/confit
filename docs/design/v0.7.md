# ConfIt v0.7 design

Design spec behind v0.7.

Status: Draft

## Motivation

v0.6 proves the loop in a container and ships the first
public alpha. Now the loop meets my own machine against
my own files. I want to use confit, and use means my real
dotfiles planning plus applying clean on my laptop. Every
gap this version closes comes from that run. Goals land
here as they appear, one run at a time.

## Objective

My real dotfiles plan plus apply clean on my laptop.
The plan reads honest on a machine confit meets for the
first time, the apply lands it, a fresh shell works.

## Goals

- Resolve latest tool releases from the releases feed, so
  a missing version always names a release holding assets.
- Give each font its own folder plus its own refresh, so
  fonts stay apart, each pair standing alone.
- Declare tool options per package, so a rust toolchain
  carries its components and my editor keeps its language
  server.
- Compare the first plan against the disk, so unmanaged
  files about to be overwritten read as impact and files
  already matching read as already in place.
- Keep plans small plus readable, so a fonts-heavy plan
  opens in an editor and history costs one shared pool.
- Export any slot into one portable file, so the applied
  slot plus named slots plus history entries all travel.
- Re-apply any past slot through apply, so one command
  covers present plus past.
- Speak bundle plus slot plus manifest, so the command,
  the portable file, the stored copy, and the readable
  view each own one noun.
- Delete named slots, so retired experiments free their
  bytes.
- Validate manifests against a schema, so every bundle
  proves its shape before anything applies.

## Plan

Each part below takes one goal from above and scratches the
behavior I want. Each part turns final when its
`.local/plans` pass says it builds.

### Latest from releases

An omitted version resolves through the releases feed,
latest first. The releases feed carries assets, so it
carries resolution too. An empty feed fails
the plan naming resolution.

### One folder per font

Each font lands flattened under its own folder under the
data fonts folder. Each font carries its own cache refresh
scoped to that folder, so refreshes run apart, each inside
its folder. Each font owns its installer outright.

### Toolchains carry their extras

My laptop apply installed the rust toolchain and skipped
rust-analyzer, so the editor lost its language server.
Tool options close that gap declaratively. Each
package declares its backend options beside its version,
so the toolchain plus its components install as one:

```lua
mise.package({
  name = "rust",
  version = "1.83.0",
  bin = "rustc",
  options = {
    components = { "clippy", "rustfmt", "rust-src", "llvm-tools" },
  },
})
```

The shared config renders one entry per tool, version
plus options together:

```toml
[tools]
rust = { version = "1.83.0", components = ["clippy", "rustfmt", "rust-src", "llvm-tools"] }
```

Options stay generic. One table carries whatever the
backend honors, components today, targets tomorrow. A
fresh install converges with its extras included, so the
editor finds its language server on the first shell.

### First plan reads the disk

A missing state slot opens the first run. The plan
compares desired documents against disk bytes.
Disk-identical documents read as already in place and leave
the add count.
Disk-differing managed paths read as overwrites the apply
will replace, flipped disk to desired. Missing disk paths
read as creates. Once the slot exists the state turns into
the source of truth and the steady behavior returns.
Disk against state shows drift, and a new plan against
state shows the lifecycle. The comparison takes a side order, so
the first run reads disk-first natively.

### Small plans share blobs

My dotfiles plan weighs hundreds of megabytes, mostly
fonts, and every stored copy repeats those bytes. Each
slot stores a manifest holding paths plus kinds plus
modes plus hashes plus hooks, while binary bytes live
once in a shared pool under content hashes. Text plus
structured plus rc plus link payloads stay inline because
they read well and diff well. Opaque files plus tree
members move to the pool compressed. Measurement on my
example 3 plan decided the shape:

| What | In the file today | Raw bytes | Compressed |
| --- | --- | --- | --- |
| 1 opaque file | 177 MB base64 | 133 MB | 42 MB |
| 96 font members | 324 MB base64 | 243 MB | 134 MB |
| Manifest | inline | 20 KB | 20 KB |
| Whole plan file | 501 MB | 376 MB payloads | 176 MB bundle |

Base64 alone costs 125 MB of the 501 MB file.
Whole-file compression reaches 224 MB and still opens as
one giant line, so the split carries the win.
Unchanged bytes across slots store once, so history entries
cost manifests plus one pool. The pool fills on apply alone.
Planning writes bundles holding their own blobs, so binaries
that never apply never touch the disk. Bytes live while a
slot references them, and slot removals prune the rest. The
manifest pretty-prints to kilobytes and opens in any editor.

### One file travels

`export` packs any slot into one portable `.cb` file holding
the manifest plus only its referenced blobs. The picker
reads `#N` for history entries, `@name` for named slots,
and bare names the applied slot:

```sh
confit export
confit export @personal
confit export #2
```

Named slots store as manifests in the same shared
structure, so they cost kilobytes until exported. Export
takes an optional path and auto-names the file from the
slot otherwise. It writes a file and prints the path.
Bytes travel by file, text travels by stdout. A
`--manifest` (`-m`) flag prints the pretty manifest JSON
to stdout for the picked slot instead of writing a file,
so one command covers the portable file plus the readable
view. History numbers run newest-first from one, so `#1`
names the just-previous entry everywhere.

### Applying the past replaces recover

Past slots apply through the same door as fresh bundles.
`apply --bundle` learns the same picker and replaces the
`recover` command, so applying `#1` re-applies the
just-previous entry through the usual preview plus
prompts. The apply help explains the picker beside the
bundle flag, and every slot picker in the app shares the
one numbering.

### Words mean one thing

The word plan comes from terraform, and terraform plans
hold paths plus a remote diff. They preview while the
cloud applies. Paths travel, bytes stay remote. Our
artifact is another kind entirely. One file holds the
manifest plus every blob, so any stored state recovers
from the bundle alone. Calling that file a plan promises
a preview and delivers a payload. The `plan` command stays
because the verb is familiar, and everything it produces
answers to bundle. Plan writes bundles to `-o` paths and
prints the manifest under `--manifest`. A bundle is the
portable file holding one manifest plus its blobs, named
`.cb`. A slot is any stored bundle. It holds the current one, one history entry, or one named
slot. A manifest is the readable metadata inside a bundle,
the closest thing to what other tools call a plan. Apply
moves bundles across slots. It applies the bundle, copies
it to the current slot, and pushes the previous current to
the front of history, dropping the oldest past the kept
count.

### Named slots delete

A delete command removes one named slot by its `@name`.
The manifest drops and unreferenced pool bytes prune with
it, so the bytes leave together with the name. History
rotates on its own and the current slot stays, so delete
names `@name` slots only.

### Manifests validate

Every manifest validates against a checked-in JSON
schema generated from the app's own types. Every bundle
proves its shape before anything applies. Open leaves stay
open. Untyped values validate as anything today and
tighten later.
