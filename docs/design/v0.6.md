# ConfIt v0.6 design

Design spec behind v0.6.

Status: Sealed

## Motivation

v0.5 proves the file loop in a container. Files land, drift
shows, recover works. Installing mise itself already
composes from primitives, fetch plus unpack plus an opaque
document. The missing piece sits one step later. After
confit writes a tool config, the tool needs its own
post-config step, and confit cannot delegate it yet. Mise
installs its packages, fc-cache rebuilds its cache, brew
bundles a Brewfile. Confit work is the initial setup plus
the handoff. This version builds the handoff.

Two gaps block that. Post-config steps run by hand. Plans
have no home, so switching profiles means remembering tmp
paths. This version closes both.

## Objective

Confit alone configures the example 3 container from nothing
but system-wide software. Primitives install mise, hooks
hand tools their post-config steps, files land around them,
a fresh shell works.

## Goals

- Let configs carry post-config steps as hooks, so tools
  finish their own setup after their config lands. Plan lists
  hooks for apply to run.
- Store named plans with `@` sugar, so switching profiles is
  one command each way with the rendered result replaying
  directly. The single state slot keeps its job.
- Remove `--state`. The fixed slot serves every run.
  Experiments plus backups plus sharing run on saved plans.
- Take a `mise.package` table with sensible defaults, version
  included.
- Settle patch collisions by declaration order, so the
  profile author moves the winner by moving lines.
- Let configs require sibling configs, so a package without
  its installer fails the plan naming both.
- Collapse many-file archive sets into one tree document, so
  fonts read as one plan line either way.

## Plan

Each part below takes one goal from above and scratches the
API, the expected outputs, and the behavior I want. Nothing
here is final until its `.local/plans` pass says it builds.

### Hooks

Some tools finish their own setup after their config lands.
Mise installs its packages, fc-cache rebuilds its cache.
Confit writes the config and delegates the step. Post-config
steps attach to the config they follow, so they ride configs
beside documents plus patches.

I think hooks plugin-first. Mise or a nerd font installer
declares them, my profile stays clean. The API stays shared,
plugins use the same calls user code uses, and a user
composes whatever they want. A plugin runs nothing unless my
profile requires its config. That table is the enablement
switch. One-shot setups ride a hooks-only config.

```lua
local c = confit.config("mise")
c:add_hook(confit.hook.run({ "mise", "install" }, {
  path = { confit.path.home(".local/bin") },
  when = confit.runtime.in_path("mise"),
  checks = { confit.runtime.in_path("bat") },
  timeout = "10m",
}))
```

An argv list executes directly, so every hook reads as words
without a shell in between. Four opts shape the run.

- `path` extends PATH for the hook subprocess alone, so the
  mise I just installed resolves.
- `when` gates the run on runtime conditions, evaluated in
  Rust before the hook starts.
- `checks` prove the run with the same shapes. Passing
  checks skip the hook, failing checks run it, still-failing
  checks fail the apply.
- `timeout` caps the run at `10m` by default, with
  Lua-shaped durations.

Unknown fields fail as plan errors through the same two
layers. The preview prints each hook as
a `! run:` line with the resolved absolute binary, and the
literal `yes` covers files plus hooks together. Plan builds
data alone, apply executes. Documents materialize before any
hook runs. Hooks run post-materialization alone.

Hooks ride the plan like documents. Plan and state share the
exact shape, so hooks persist into state as pure data: argv,
gates, checks. Each plan re-evaluates the checks. A failed
check reads as drift, the hook counts as not applied and
runs again on apply. A passing check reads as applied and
skips.

Ten packages declaring the same install hook run it once. I
merge hooks with identical argv plus path into one run in
first-declaration order. Gates join with OR, checks join
with AND, timeout takes the max. Each check binds to its own
gate: the merged run verifies only the checks whose gates
held. A closed gate warns and excuses its check. Hooks differing
in argv or path run separately.

### Gates and checks

A closed `when` gate warns the post step cannot run, with
the gate named. A passing check skips the hook with a
`skipped:` line, the work already stands done. Gates evaluate
in Rust at apply time. `in_path` reads PATH,
`exists` stats the path, `env_eq` plus `env_set` read the
environment, `all` plus `any` plus `nop` compose. The
evaluator reads path, file, and environment shapes. Anything
else fails as a plan error.

`checks` prove the run with the same shapes, before plus
after. Passing checks skip the hook with a `skipped:` line,
the desired end state already holds. Failing checks run it,
still-failing checks fail the apply, abort the rest, exit 1.
The `mise install` hook proves itself with the binaries it
was supposed to produce.

Resolution happens at plan time against the engine process
PATH. The engine never applies profile PATH prepends to
itself, so a malicious prepend cannot redirect resolution.
`path` prepends dirs to the hook subprocess environment
alone, for the mise I just installed into `.local/bin`.
The preview shows the absolute, so review sees the exact
binary that runs. A timed-out hook fails like a nonzero
exit.

### Hook output

Hook output streams into the run log file. The terminal
shows `hook n of m` plus a spinner, nothing else. I read
logs in the log file when a hook fails, same as collisions.

### Named plans

`-o @work` stores the rendered plan under the user config
folder as `plans/work.json`, pretty printed like any plan.
`--plan @work` resolves the same path. `@` with an empty
name or path separators fails as a CLI error.

```sh
$ confit plan work.lua -o @work
Plan: 3 to add, 0 to change, 0 to destroy.
$ confit plan personal.lua -o @personal
Plan: 5 to add, 0 to change, 0 to destroy.
$ confit apply --plan @work
$ confit apply --plan @personal
```

Switching is one command each way. The rendered result
replays directly, evaluation plus fetching costs stay paid
from rendering. The single state slot does its normal job
underneath. It diffs the incoming desired set against what
was there, and cleans up what the new set drops.

### `--state` removal

The flag goes away. Every run reads plus writes the fixed
slot. Saved plans cover the old uses. Experiments point
`--plan` at a rendered file. Backups copy a plan file. Sharing
sends a plan file. One user holds one applied result, and one
slot mirrors it.

### Mise package table

```lua
local bat = mise.package({
  name = "bat",
  version = "2024.1.0",
  rc_builder = function(rc)
    rc:alias("cat", "bat")
  end,
})
```

Every field stays optional except `name`. Omitted version
writes `latest`, omitted builder adds no entries. The table
shape lets the LSP complete each field, and later options
gain keys instead of positions.

### Requires

I keep forgetting the installer config beside `mise.package`.
The rc entries sit inert behind their gates, the tools
declare, mise never arrives. So configs require siblings:

```lua
-- inside mise.package, before returning the config
config:require("plugin:solrachq/mise:install", "Add mise.install() to the profile configs.")
```

`mise.package` injects this itself. My profile lists the
installer once, every package points at it. A missing target
fails the plan naming the requiring config plus the absent
one, with the hint on its own line when the plugin provides
one:

```sh
config "bat" requires "plugin:solrachq/mise:install" config
hint: Add mise.install() to the profile configs.
```

I walk the closure, so requires on required configs
check too. Cycles resolve fine, because require checks
existence alone and sorts nothing. Require checks, the
profile composes.

### Collision order

Rc plus structured patches share one sort, so the rule
covers both. Patches sort by priority desc, then config
declaration order. Moving a config inside the profile
`configs` table moves its collision winners. Collection
preserves declaration order today, the sort drops it. The
sort carries an order index per patch, stamped at
collection. Owner leaves the comparator.

### Tree documents

`compressed` fits single-file picks with an explicit mode.
The mise binary takes `mise/bin/mise` and places it with
`755`, and its drift reads per file. Fonts want the other
shape. Ninety-six files land in one folder, and I want one
plan line either way, never a wall of adds.

I think tree documents. One archive builds one document
holding many files. The callback keeps its shape, member
path plus info plus content, and returns a destination
relative path or nil instead of a document. Picking plus
flattening fall out of the same function I already write:

```lua
local archive = confit.resources.fetch_file(font_url)
local fonts = confit.document.tree(archive, confit.path.data("fonts"), function(path, _, content)
  if not path:match("%.ttf$") then
    return nil
  end
  return path:match("([^/]+)$")
end)
```

The first apply reads as one add:

```sh
+ tree ~/.local/share/fonts (96 files)
```

A repeat apply against an unchanged pack reads as nothing.
A real content change reads as one update with a count:

```sh
~ tree ~/.local/share/fonts (2 of 96 files changed)
```

The changed members list in the run log. Writing to disk
stays per file underneath that line. Files whose content
changed get rewritten, members the new tree drops get
removed, and files I placed by hand stay untouched. The
summary is a display decision. Member modes inherit the
archive executable bit, so fonts land `644` with no extra
API. An empty pick fails as a plan error naming the
filter, since fetching an archive to keep nothing is a
mistake in my callback.

I think a nerd fonts plugin beside mise. `font` takes the
name plus an optional version and builds the tree, `init`
holds the shared `fc-cache` hook. The hook carries no
checks, a cache rebuild holds no stable disk proof, so it
fires every apply. My profile lists the installer once
beside its fonts, same as mise.

## Out of scope

Remote execution, hook output parsing back into plans, plan
garbage collection under `plans/`.
