# ConfIt v0.1 design

Design spec behind v0.1-pre-alpha.

Status: Implemented (sealed 2026-09-09)

## Motivation

My old dotfiles piled machine-specific special cases onto static configs
until every edit felt risky. The Python around them gave no preview of
what a change would do. Generated files got fixed by hand. And everything
needed a bootstrap step just to install Python.

## Objective

Make the `plan` command work, proven by `examples/0-basic_tool`: one tool,
one alias, one package, planned end to end.

```lua
-- examples/0-basic_tool/tools/bat.lua
local bat = confit.tool("bat", {
  install = confit.mise.package({ name = "bat" }),
})
bat:alias("cat", "bat")
return bat

-- examples/0-basic_tool/profile.lua
local bat = require("tools.bat")
return {
  shells = { "bash" },
  tools = { bat },
}
```

Expected output:

```sh
~/.bashrc: rc ← bat
  + alias cat = bat (bat)
~/.config/mise/config.toml: toml ← bat
  + tools.bat = latest (bat)
plan: 2 create, 0 update, 0 unchanged
```

## Goals

- Idempotent changes: same profile, same result, safe to re-run.
- Diffs you can read before anything is written.
- Flexible configuration: conditionals and composition, not special cases.
- Reproducibility: the plan file fully describes the result.
- Reusability: profiles share tools without redoing config.
- LSP help: a Lua API discoverable from the editor (stubs ship in
  `stubs/`), no key names to memorize, no silent ignores.
- One static binary, no bootstrap step.

## Plan

### Idempotent changes: borrow state from IaC

`plan` diffs three things: desired (Lua evaluated to data), previous (the
state file), actual (the filesystem). That is the Terraform loop, and it
needs an atomic unit to compare. The **artifact** emerges here: a file
defined by its path, the only thing that touches disk, the only thing
hashed. Tools contribute data toward artifacts and stay invisible to
state, so renaming a tool or moving a contribution never invalidates a
hash.

State is a JSON file mapping `"kind:path"` to `{ data_hash, output_hash,
data? }`. Two hashes because "I changed my mind" and "someone hand-edited
the file" are different facts.

### Readable diffs: winners on screen, losers on request

The summary lists every entry with its winner tool. `--conflicts` names
the loser on changed lines. Full winner chains wait behind `explain`.

### Reproducibility: canonical bytes before hashes

Lua map iteration order is random, so maps sort recursively at
canonicalization. Ordered lists (`env`, `profile`, `init`) keep
declaration order instead, because there order is meaning: base export
first, conditional overrides after, init steps in sequence.

Each merged artifact serializes to fixed JSON bytes and hashes with
SHA-256. The plan id hashes the sorted per-artifact hashes, so artifact
order never matters. `_shadowed` losers and `_blame` attribution stay in
the plan file for inspection but out of the digest: debug info must never
flip winner identity, and changing only losers is not a change.

### Flexibility: Lua builds data, core decides

Profiles return the whole resource graph, tools contribute through handle
methods. The model carries conditions (`when`) as unevaluated data so
plans can show every branch; DSL wiring for conditional contributions is
future work. Same name with structurally different `when` means
co-winners, rendered as independent `if` blocks in declaration order.
Last match wins at runtime; `elif` chains would read backwards against
declaration order.

Data-first at the boundary: artifact tables must survive a JSON
round-trip, functions and userdata are rejected naming tool and field.
Rendering to bytes happens only in `apply`, so `plan` never executes
anything user-defined beyond building data.

`rc` is the only bespoke schema, because no generic merge expresses env
shadowing, alias maps, and ordered init blocks in one per-shell file.
Everything else is a generic kind at the author's discretion.

### Reusability: validated builders, one channel per method

`confit.tool` returns userdata holding a Rust-owned builder, mutated in
place. A plain table would let authors hand back any shape; the builder
forces every contribution through a validated constructor, so bad shapes
fail at the boundary. Method syntax (`:env`, `:alias`) marks Rust-owned
mutable state, plain calls (`.`) mark constructors and data.

One method per contribution channel because each feeds a different merge
rule: env shadows by structural equality, aliases merge key by key, init
dedups, profile entries carry prepend/append ops. `install` rides in the
constructor because a tool has at most one installer spec.

Sharing is legal by design: two tools may write one path (mise config,
rc files), same kind merges per its rule, same path with a different kind
is a plan error instead of a guess.

### Execution order matters: last wins

Require order is meaningful. If two tools touch the same env or alias,
the one required last wins:

```lua
local a = require("tool_a")
local b = require("tool_b")
```

can plan differently than the reverse order. This differs from Terraform:
there each resource is immutable and others only reference it. Here
artifacts are built from fragments and merged in execution order. That
decision can change in the future, but for now it is what it is. Order
matters by the nature of the tool.

That said, a tool touching envs or aliases outside its domain is weird.
Cross-domain writes stay legal (shared files need them) but they smell.
Same-domain contributions are the norm.

### LSP help: LuaLS plus stubs

Lua is the embedded language: light, small binary cost, everyone knows
it. The deciding factor is LuaLS. No other small scripting language gives
that editor support, so `stubs/confit.d.lua` gives autocomplete plus a
check against writing something stupid.

### One static binary: Rust plus vendored Lua

Zig is out for anything needing heavy third party packages: weak string
handling, and the templating and codec ecosystem barely exists. Go lacks
the abstraction level for this kind of project and its Lua support is
thin. Kotlin ahead-of-time builds are too big for curl-and-run. Rust has
`mlua`, the best Lua layer available (cof, cof, aside zua), plus the hashing,
templating, and serialization crates ready.

## Out of scope

`apply`, `explain`.
